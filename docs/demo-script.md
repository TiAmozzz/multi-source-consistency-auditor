# 作品演示录制方案

当前项目中未生成演示视频，也没有虚构视频链接。以下步骤用于录制真实运行过程。

## 录制前准备

1. 使用 1920×1080 屏幕，关闭聊天、邮箱和含个人信息的窗口。
2. 打开终端并进入项目根目录。
3. 预先执行一次测试，确认环境正常，但不要在录制中伪造执行结果。
4. 录制工具可使用 Windows 自带的 `Win + G` 录屏，或 OBS Studio。

## 建议时长

3—4 分钟。

## 演示流程与讲解词

### 1. 项目用途（约 25 秒）

画面：展示项目根目录和 README。

讲解：

> 这是多源资料一致性核验助手。它用于检查同一个业务编号分散在多个表格和文档中时，是否存在资料缺失、重复、金额或日期不一致。项目以 Agent Skill 为入口，但核心是本地运行的 Python 核验引擎。

### 2. 展示输入资料（约 35 秒）

画面：打开 `examples/procurement/input`，展开合同文件夹。

讲解：

> 示例包含采购台账 Excel、采购申请 CSV、两份 Word 合同和一份 PDF 合同。工具一次读取多个来源，不要求指定账本，也不需要转换原文件。

### 3. 展示配置（约 30 秒）

画面：打开 `examples/procurement/profile.json`，高亮 `identifier`、`sources`、`fields` 和 `checks`。

讲解：

> 用户通过配置定义业务编号、文件来源、字段别名和检查规则。更换配置即可用于其他业务场景，不需要修改核心代码。

### 4. 实际运行（约 45 秒）

画面：在终端执行：

```bash
python multi-source-consistency-auditor/scripts/audit.py \
  --profile examples/procurement/profile.json \
  --output examples/procurement/output \
  --format xlsx \
  --format pdf
```

讲解：

> 输出格式由用户选择。这里同时生成 Excel 和 PDF 差异汇总。原始文件只会被读取和哈希校验，解析器处理的是临时副本。

### 5. 展示差异结果（约 50 秒）

画面：打开 `differences-summary.pdf` 或 Excel。

讲解：

> 系统关联出五个采购项目。P-2026-002 的采购申请金额为三千二百元，合同金额为三千五百元，因此被标记为错误。另外三个项目分别缺少采购申请或合同文件。报告同时保留原文件、行号、页码和原文。

### 6. 展示安全边界（约 25 秒）

画面：回到终端，展示测试输出，再打开 `docs/test-record.md`。

讲解：

> 全部自动化测试均已通过。示例运行前后，五个源文件的哈希完全一致。程序不联网、不上传资料，也不会修改原始文件或其格式。

### 7. 收尾（约 15 秒）

讲解：

> 这是一个可本地复现、可配置、可测试的多源资料核验工具，既可作为 Agent Skill 调用，也可以直接作为命令行工具使用。

## 上传说明

录制完成后由项目负责人检查视频是否清晰、是否包含敏感资料，再上传至比赛允许的视频平台。未经负责人确认，不应公开分享源文件或完整报告。
